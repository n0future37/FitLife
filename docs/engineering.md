# 执行与并发边界

MySQL持有业务事实、确认、请求身份和会话租约；写入先锁本人用户行，独立事务/Session。
这是清晰可验证的首版串行写保护，同一用户的热点读写会排队，未声称高吞吐。
同步SQL在API线程池执行，模型/MCP/Redis使用异步I/O；没有共享跨任务Session。

只在同一批调用全部是允许的只读工具时并发，默认上限2，结果按call_id回传；
含候选的调用顺序执行并在候选产生后停止。工具依赖仍由服务端检查，不能靠并发绕过。
模型暂时错误最多重试1次；只读工具超时最多重试1次；候选超时不自动重试。
恢复同请求可找回已产生候选，确认绑定内容/版本并保证一次业务写入。

正式server入口默认启用Redis全局容量2（进程内仍最多2）；多个实例共享环境前缀ZSET。
Lua脚本用Redis时间原子清理过期租约/申请名额，释放只删自己的随机token；崩溃后TTL回收。
Redis失败503，满额429，无静默放开。MySQL的运行nonce保护旧执行者写入。
按需要可用--local-limit显式仅单进程限制，不能据此宣称跨进程容量保护。

测试DB3、开发DB2，键前缀fitlife:test:/fitlife:dev:；逻辑DB和键前缀不是账户权限隔离。
本机服务命令可传--redis-credentials-file E:/Work/Config/Redis/.env读取已有安全配置，
不在命令参数传密码，不改公共Redis配置。也可提供FITLIFE_REDIS_PASSWORD进程变量。

活动明细默认最多100条，可传limit/offset；record_count与recorded_minutes始终为整个区间
汇总，不是本页合计。计划进度采用有界聚合。/ready检查数据及容量服务；/health只说明进程可访问。
当前测试验证机制正确，不将固定模型/短延迟模拟当作真实模型性能或生产容量指标。

检验命令：fit解释器`-m pytest --integration`，本机需测试库安全凭据及Redis配置；
只读工具并发、候选超时、故障恢复、权限和同确认并发均有规则测试。
Redis测试只创建本次随机check-键，结束只删自己的键，绝不清空DB3或其他项目内容。
