# FitLife架构入口

当前0.6核心增量见[计划/评测/可靠执行](core-v06.md)，主从架构见[主从Agent与迁移](agent-migration.md)、[模型与协议](model-profiles.md)、
[能力成熟度](capabilities.md)和[评测口径](evaluation-v05.md)。

主Agent提取任务并校验覆盖，身体、饮食、运动Agent按依赖读取本人事实和提出候选；
综合步骤解释来源和局限，确认接口执行服务端事务。主从共享执行预算，用户身份来自认证API，模型没有确认工具。

工具/MCP只负责契约和传输，业务规则、归属、数值计算、版本和写入放在服务端。
MySQL是权威数据，Redis控制共享容量；同步SQL使用独立Session，API线程池和独立MCP进程隔离阻塞。
只读工具及独立领域有界并发；失败、超时、重试和nonce均可追踪。

原0.4单Agent方案、源码和真实评测保留，路径见STATE及artifacts/releases/fitlife-0.4.0-20261102。
本次新增主从能力独立验收，不以架构变化本身宣称成功率提高。
覆盖检查只能验证已提取的任务；漏提取仍需由用户任务和最终状态评测发现。

密码、令牌、媒体与原文不进入普通日志和发布包。项目尚未对外发布；开放式安全回答、
第二平台、本地模型、复杂视觉质量和生产容量分别保留验证边界。
