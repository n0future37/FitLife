# 多轮会话与结构化记忆

会话保存临时需求和必要回答，画像保存经确认的目标/偏好，计划及活动是业务事实。
模型每轮重新查事实；本轮要求优先于旧聊天。最多提供最近6个成功回合、合计12000字符，
不是把全部历史塞入模型。画像版本变化后只使用新版本下的聊天，防止旧目标或已删除偏好复活。
不将聊天自动归纳成长期记忆，不依赖向量库。

`POST /conversations`创建本人会话，`GET /conversations`列最近50个；
`GET /conversations/{id}`返回最近50回合及刷新后的候选状态。
`POST /agent/requests`可附conversation_id；不附时保持原单轮行为。
每个会话同一时间只有一个执行请求，数据库租约和执行nonce跨进程生效。
请求键绑定用户、消息摘要和会话，重复请求返回原结果，不重复收费调用模型。

新消息会撤销本会话以前的待确认候选（包括查询消息），因此修改要求后旧卡片不能保存。
这是保守的首版交互规则，不用模型猜测是否撤销。确认仍需用户操作专用接口。
工具产生候选后若执行中断，重试相同请求可从数据库找回原候选，跳过模型；
过期执行者的工具写入和完成回调都会被nonce阻断。

`GET /profile`查看记忆值/来源/更新时间；画像更新候选用于更正。
`POST /profile/forget-actions`提交fields列表，用现有确认接口删除字段。
删除后保留版本及不含旧值的user_deleted来源标记，旧画像确认不能重新覆盖。
删除画像字段不删除计划或活动；确认候选作为业务操作证据暂保留，不能宣称全系统隐私抹除。

`DELETE /conversations/{id}`删除聊天正文、上下文快照和缓存回答，保留幂等墓碑，
使旧请求不能复活。运行中拒绝删除，旧待确认候选失效；已保存业务事实仍保留。
本人令牌才可读写；模型工具没有删除聊天、确认或跨用户入口。
尚无自动保留期限清理，部署前需明确保留策略；普通运行日志不保存个人原文。

## 对话名称（2026-11-03）

新会话先显示“新对话”。首次成功回合（包括补问或待确认草案）之后，Agent使用fast模型概括主题，建议6至16字、最多40字。页面下拉列表显示真实名称；点击“重命名”可填写、保存或取消，刷新后保留。

名称单独保存title/title_source/title_revision，不混用对话轮次version。source为pending/agent/user；用户命名后后续轮次不自动覆盖。PATCH /conversations/{id}/title提交title和revision，只能操作本人会话，旧版本409；空白、过长、换行或控制字符拒绝。名称按文本渲染，HTML字符不会执行。

辅助命名每轮至多一次、无工具、输出128 Token、请求4秒/辅助段6秒、关闭重试与备用；复用主任务的模型调用和Token账本，并计入原总运行期限。若预算不足或剩余时间不足9秒则不生成。它不增加业务工具步骤数。命名失败不改变已完成的业务结果，下一次成功请求可根据首个成功回合重试；不会改为总结最新话题。固定业务回归不会暗中启动命名模型，只有明确支持标题的测试替身参与该检查。

名称和请求完成结果在同一事务落盘；自动结果落盘时再次检查source，用户已经命名则丢弃迟到的自动标题。重复请求读取缓存，不重新命名或调用模型。恢复已有候选跳过模型，名称仍pending时留给后续成功轮次处理。删除聊天也清除名称；退出清除页面名称/下拉选项。

命名提示词版本conversation-title-v1，模型标识/参数/耗时/错误记录在原run轨迹的conversation_title阶段，不把标题、首轮私有正文写进普通运行日志。提示模型避免姓名、账号和精确健康值，属于生成约束，不宣称具备完整自动隐私识别能力。
