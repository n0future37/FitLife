# FitLife Agent 问题修复与验收

日期：2026-11-03。最终编排版本 `intent-bind-v2.2`。本轮针对新版探索实验暴露的缺陷修复，旧实验与原始分数保留。本文件是修复交付记录，不是新的方案效果对照实验。

## 已修复的问题

| 问题 | 处理方式 | 验证证据 |
|---|---|---|
| 路由将跨领域读取交给错误子 Agent，规划产生 main 执行节点或覆盖不一致 | 服务端从任务清单绑定领域、工具归属与覆盖；main 只综合。跨域只读只能绑定已有、明确声明同一读取的前序任务；未知工具、跨域写、循环与遗漏继续拒绝 | 旧三类失败回复确定性回放；自动化边界用例；真实依赖查询 |
| 模型在必要检索前生成候选 | 服务端校验 `required_reads`；失败不满足依赖，至多两次提醒，不自动猜测日期或扩大读取范围 | 提案前门控、检索失败、真实计划生成/调整 |
| 运动画像工具暴露身高与 nullable 字段，与实际业务规则不一致 | 只向运动子 Agent 暴露8个合法画像字段，省略表示不修改，明确 null/空值仍拒绝；身体信息由身体工具处理 | 实际 MCP Schema 前后快照；真实“身高＋运动目标”统一候选确认保存 |
| 将星期六误写为6，排成星期日 | Schema/提示明确0周一到6周日；对原始用户无歧义的正向星期限制，在工具前拦截显式冲突并允许有限纠正 | 星期边界测试；真实周六调整及确认后的数据库状态 |
| 模型反复提交相同无效参数，耗尽整轮时间 | 对相同规范化参数失败停止重复执行；另按已注册工具 Schema 校验类型/格式，反馈固定字段名与规则 | 重复无效参数阻断；真实本地模型修正 `2026--03` 并读取当天步数 |
| 参数错误反馈过于笼统，或直接转发错误可能泄露输入 | 使用 jsonschema 4.26.0（原环境已有，现明确声明依赖）；反馈不包含原始错误消息、输入值或用户自定义键。业务权限、事务与最终校验仍在 MCP/服务端 | 脱敏测试；本地真实恢复轨迹；完整流程回归 |
| 失败、超时、取消后步骤显示0，子任务局部轨迹丢失 | 在 finally 保存共享 Ledger 与子任务轨迹；外部取消落盘后继续传播，模型失败记录请求型号及耗时 | 失败/取消测试；103条本轮实验运行逐条核对 Ledger 与模型事件一致 |
| 实验参数判分误拒绝合法画像继承 | 运行前声明 v2 等价合同：只允许已实际读取、版本匹配且终态/关键顺序正确的画像继承或部分覆盖；显式错误不豁免 | 合同反例测试；v1规则、旧分数与旧脚本不改 |

星期保护只处理窄范围明确表达，不是通用自然语言解析器；含否定、历史、更正或歧义时不猜测。Schema 校验也不能替代业务校验、用户确认或资源归属检查。

## 日常启动配置

- `scripts/start_siliconflow.ps1` 默认采用 conservative 路由。无历史、单领域、明确只读查询使用 `Qwen/Qwen3-8B`；历史、多领域、计划及其他交付使用 `Pro/deepseek-ai/DeepSeek-V3.2`。
- 主 Agent 的路由/规划/综合使用独立 control 配置 `Qwen/Qwen3-32B`。三个云模型共用现有 SILI_API_KEY，凭据仍来自本机用户变量。
- fast/control 单次30秒，standard/complex单次45秒；瞬时故障最多重试1次，主流程180秒，既有总步骤/模型调用/工具预算仍生效。这些是执行边界，不是响应时间承诺。
- 保留本地 Qwen3 4B Instruct 只读兜底。写工具、图片或超大上下文不绕过限制；本地备用服务须已运行。云端或本地仍可能失败，不能保证所有请求都成功。
- complex 配置目前与 standard 同型号且关闭思考；参数适配能力保留，不宣称当前默认在动态调整思考强度。旧 rules 策略可用 `-RoutingPolicy rules` 显式选择，尚无理由称其优于 conservative。
- 已有8100网页服务如未重启，需按下方入口重启后使用新配置；本轮没有替用户启动常驻网页服务。本机已有本地模型进程经核实早于本轮，保持运行，未关闭旧服务。
