# FitLife 视频计数：归因、改进与对照（V3.1）

本轮只改本地视频计数工具及其验证，不训练或微调模型，不改RAG和主从Agent规划。入口仍是页面上传/后台媒体任务；用户核对并确认后成为MySQL训练事实，运动Agent可通过现有查询工具使用。当前不把它描述成主Agent自主调用视频分析工具，也不把计数结果当Agent/RAG质量指标。

使用的是公开[RepCount](https://svip-lab.github.io/dataset/RepCount_dataset.html)视频，不是用户私人视频。来自公开Lance镜像，次数逐条与[作者TransRAC标注](https://github.com/SvipRepetitionCounting/TransRAC)核对；没有声称逐条独立人工复标。新增10段在推理前按固定SHA种子与大小/标注条件选取，已有stu分组与已用片段排除；镜像train/test与官方划分不完全同义，非stu片段源视频身份不完整，不能保证全部同源镜头被识别。仅本机研究保留，不分发原视频。

## 原来为什么少计、为什么不给总数

1. **全片门槛会漏掉浅一些的重复**：旧集stu5_68参考20次却只数10次。旧角度低门槛约125°，后半段谷值升到约140–150°，无法触发同一低门槛，后半段运动被漏掉。stu1_60参考12次只数1次，姿势均值变化使状态机将多次动作合并成长段。角度图及数值保留在`baseline-angle-diagnostics.png`和`baseline-diagnostics.json`。
2. **短极值与边界**：旧实现要求极值停留0.08秒；实际约15fps时需连续约3个采样点，短暂极值可能漏过。视频开头/末尾未回到起始水平还会导致少一次；新算法保留“不把未完成往返算完整一次”的边界，因此不会为匹配标注而无条件补1。
3. **可用画面被丢弃**：任意检测到两人就清空该帧，电视/背景人物也会使片段弃权；固定一侧三个关节都可见，容易被杠铃、器械、自遮挡或裁切破坏。两名相近主体仍然应该拒绝确定总数，不能仅通过降低限制提高覆盖率。
4. **镜头切换与跟踪分裂**：开发集卧推含明显换视角。全片只选择一个主体轨迹，会丢掉其他镜头；即使分段，原关键点模型对部分卧推/裁切画面仍不可靠，不能保证恢复计数。

以上由原轨迹、开发集代表帧与新运行诊断核对；遮挡/低可见性由模型指标判断，不等于人工医学判断或动作合格判定。

## 最终改动及未采用的方案

- 保留官方MediaPipe Pose Landmarker Full v1权重与SDK，和旧版使用相同最长边640、≤15fps时间采样、最多2个人体检测，未重新训练。严格可见的单人2D角度通道优先，避免让新增跟踪逻辑破坏原本可用的信息；不可用时再选择已跟踪主体的2D/3D角度或任务相关相对位移。
- 用局部相对幅度的往返反转代替全片统一高低门槛，中心中值滤波抑制孤立跳点，最小周期0.45秒；大于0.25秒的缺口不拼接周期，末尾未充分返回时不补次数。幅度变化不等于运动是否达标，本工具不评价训练质量。
- 根据几何连续性与主体占比保留主要训练者，较小背景人不再一律清空整帧；相近主体歧义超过限额、信号覆盖不足70%、长缺失仍不给总数。这里是几何跟踪，不是跨镜头生物身份识别。
- 识别突发镜头切换，按镜头独立选主体/信号、统计可见往返，不跨切换拼半次。无法识别是否回放，页面明确提示核对。
- 尝试过画面PCA周期后备，开发集没有带来可靠恢复，已归档候选源码/轨迹，未进入最终程序。30fps候选增加耗时并发生跟踪回归，其43/80试跑由代码哈希保护结束，完整原数据保留，不混入正式成绩。V3.1采样/后备决定有时间记录，早于查看该候选的新增集输出；新增集随后被试跑复用，最终结果只作重用对照，不称严格独立盲测。最终冻结后未再按结果调参。

## 正式对照协议

20个独立片段（原10、另取10）×两种算法×两次重复＝80次运行，版本顺序按片段/轮次交替，单并发，同解释器、SDK与权重。V2使用改动前归档源码并显式指定同一模型路径；V3.1与V2均≤15fps。样本/权重/代码SHA、参数与环境见`paired-final-v31/protocol.json`和`source-frozen.zip`。

完全正确和误差≤1的分母包含不给总数的运行；null不补0。MAE只在给出总数的运行中计算，同时报告覆盖率和共同给数样本误差。重复运行不代表更多独立片段；两次主要观察本机稳定性。离线数值评测不写业务库，权限/确认/幂等由软件回归及真实页面闭环单列验证。

## 工程验证和证据边界

Windows完整回归172/172通过，真实浏览器12项检查通过（自动39、模拟本人更正40后确认，原证据保持39）。这条UI验证不作为人工标注或准确率样本。软件检查与浏览器结果见本批次`regression.xml`和`ui-evidence/`；不能将软件测试通过当准确率。确认前不写入、用户更正、自动证据不可改、重复确认和取消/来源校验沿用并回归。页面“覆盖率”改称计数信号覆盖率；分镜头/回放风险明确提示。

该实验未重新测量餐食、训练模型或改动RAG/主Agent。上轮267项证据在本轮开始和封存时逐项哈希检查，原0/20准确率与所有失败保持原样。Linux媒体镜像仍是上轮网络下载阻断后的待验证状态，本轮不借用旧Linux通过记录。
